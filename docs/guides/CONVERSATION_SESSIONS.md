# 人设与会话存档表

控制台“人格与角色 → 会话存档表”展示群、普通私聊、管理员私聊所对应的人设及 DSH 对话 ID。按“聊天对象 × 稳定人设身份”分开保存；相同数字的群与 QQ 私聊各有独立会话，同一个人设可以有多段历史。

## 使用行为

- A 切到 B：先撤销旧调用令牌和待投递任务，再清空 A 的 DSH 待处理队列、取消其在途回合；保留 A 的历史，不归档销毁它。只有当前人设可以收发和被唤醒，暂停存档不会自动运行。
- B 切回 A：继续该对象的 A 最近使用且权限模式兼容的存档，复用原来的 DSH 对话 ID。可在表中点“继续此会话”选回更早的某段存档，同时选择对应人设。
- “新建会话”：保留旧记录、选择一个新的空存档；下次正常唤醒才实际创建 DSH 会话。点击操作本身不发送 QQ 消息，不调用付费模型。
- 首次升级：已有活动会话只读映射到原人设，保留原 ID。查看表不会改写文件；第一次真正需要保存时才写入新格式。其他群与私聊不受影响。
- 全局默认人格变更只切换沿用全局的对象；显式指定某个人设的对象保持原选择。重命名人设保留稳定身份和原会话；删除后重建同名角色是新身份，不会复活旧角色历史。

人设的模型对话历史各自独立；群/私聊的近期真实消息、未读、话题和成员印象仍属于聊天对象，切换后可用于了解当前聊天情况。它们不会恢复成 A 离开时的旧副本，也不会把 B 的完整模型内部对话拼到 A 中。最近消息仍受原来的保留窗口约束；本功能不承诺保存每一条永久群消息。

“最近启用”表示存档被创建或选择的时间，不是逐条消息的发送时间。长期运行的活动会话不需要每轮重写这张表。

## 重置、故障与权限

清除当前上下文会把该旧模型 ID 标记为失效；清空工作区会使全部旧模型存档失效，避免下次切换把已清除的上下文接回来。表中仍保留历史归属记录用于识别，不允许“继续”已经失效或权限模式不兼容的会话。

暂停取消失败时，本次切换明确失败，并留下阻断标记；程序不会悄悄恢复未确认停止的旧任务。操作“新建会话”会再次确认旧任务停止后恢复使用。切换与重置交错时校验会话代际，旧操作不能把清空的会话放回来。

如果模型后端已经删掉记录，单靠 ID 无法恢复其内容；下次使用时会检测不存在，标记旧记录失效并创建新的模型会话。普通的模式或工具预设变化沿用原有权限校验，不能将管理员完整工具会话复用到普通群。

账号权限与 QQ 聊天身份分开：只有控制台管理员能查看和切换这张存档表。普通账号只在独立页面查看获授权对象的会话数量、当前人设和估算费用，不能读取 DSH ID、聊天正文或管理接口。智能体也不能管理存档表。

## 数据与接口

使用 `state/conversation-sessions.json`，版本 1 包含 `personas`（稳定身份）、`records`（聊天对象、人设身份、DSH ID、权限模式、时间与阻断/失效标记）、`selected`（每个聊天对象当前选择）。原 `sessions.json` 仍保存活动映射，启动后可从存档恢复活动 ID。

旧数据不被删除；新增文件采用严格格式校验和原子替换。损坏、未来版本、未知字段、无法读取或操作期间被外部替换时均停止改写，不用空表覆盖。切换网络等待后重新读取存档，避免不同群的并发操作互相覆盖。

| 接口 | 行为 |
| --- | --- |
| GET `/api/conversation-sessions` | 返回可配置对象、稳定人设身份、历史记录和当前选择 |
| POST `/api/conversation-sessions/activate`，`{id}` | 切换人设并继续指定存档 |
| POST `/api/conversation-sessions/new`，`{key}` | 为该对象当前人设选择一个新空存档 |

接口仅管理员可用，原 `/api/conversation-roles` 与 `/api/group-roles` 保持兼容，选择人设时会使用同一套存档切换逻辑。

会话历史持久化与供应商的上下文缓存是两回事。保存 ID 能延续历史，但缓存由供应商管理，可能过期，也不保证复用旧会话一定省钱。仍应观察输入、缓存命中和输出用量。

## 验证

`node scripts/test-conversation-sessions.mjs` 验证迁移、恢复、重启、改名、删除重建、权限、重置、故障和跨对象并发。`node scripts/test-session-switch-races.mjs` 验证跨重置和旧发送队列竞态。`node scripts/test-conversation-sessions-ui.mjs` 运行真实隔离 Bridge 的浏览器测试，覆盖操作与手机布局。测试不发送真实 QQ 消息或请求付费模型。
