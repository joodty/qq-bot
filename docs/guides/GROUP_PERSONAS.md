# 每个会话独立选择人设

在控制台“人格与角色 → 按会话设置人设”中，为允许群、允许私聊对象和管理员私聊选择已有角色，再点击该行“保存”。选择“沿用全局”表示没有覆盖设置，之后跟随全局默认人格变化。管理员是私聊对象的一种身份，不是第三种会话类型。同一个数字的群和 QQ 私聊分别配置，管理员同时出现在私聊允许列表时只显示一次。

设置人设不会增加聊天权限或工具权限。界面会注明当前模式没有开放的会话；例如管理员不在私聊允许列表时，普通模式下仍受允许列表约束，封闭 Agent 模式仍仅允许管理员私聊。全局静默开关与原来的权限规则保持生效。

实际人设变更时，停止当前会话的排队与在途模型任务，并把旧模型会话作为存档保留；切回原人设时默认继续它最近的兼容存档，使用原来的 DSH 对话 ID。初次使用某个人设时，下一次正常唤醒才创建模型会话。近期消息、未读、话题与成员印象保留，其他会话不变。重复保存同一选择不会重建会话；显式选择与全局相同的角色也不会重建，但之后不再跟随全局变化。保存不会自行唤醒机器人或发送 QQ 消息。详见[会话存档表](CONVERSATION_SESSIONS.md)。

解析同时用于聊天提示、两代仿真的唤醒/摘要/提醒以及 `qq_get_prompt` 的完整角色卡。智能体只能读取自己会话的人设，不能读取或修改管理端的会话人设列表。

## 保存与旧版迁移

`state/conversation-roles.json` 格式为：

```json
{
  "version": 1,
  "roles": {
    "group:456789": "咸鱼同桌",
    "private:123456": "小橘"
  }
}
```

新文件不存在时，只读旧的 `state/group-roles.json` 并映射为群会话设置。两个文件都不存在时全部沿用全局。升级或读取不会自动写文件、重建会话；第一次有变化的保存会把旧的全部群设置和新设置一起原子写入新文件，旧文件原样保留。新文件一旦存在就作为唯一来源，不再合并旧文件，避免恢复沿用全局后旧设置复活。

读取失败、格式损坏或不支持的版本会拒绝改写并显示错误，不会用空配置覆盖数据，也不会静默退回旧文件。配置与模型会话状态分开，重置会话不会删除设置。恢复沿用全局时删除对应映射。

修改角色正文沿用原来的即时生效行为。重命名角色跟随更新所有会话映射；删除仍被任一会话单独引用的角色会被拒绝，请先解除引用。移出允许列表的会话不再显示，但配置保留，避免重新加入后丢失设置。

## 管理接口

- `GET /api/conversation-roles`：返回全局默认、角色选项、可配置会话及当前聊天权限状态。
- `POST /api/conversation-roles`：`{"key":"private:123456","role":"小橘"}`；`role:null` 恢复沿用全局。只接受允许列表中的群/私聊和已配置的管理员私聊，以及已有角色。
- 旧 `GET/POST /api/group-roles` 保持群接口兼容；POST 仍使用 `{"groupId":"456789","role":"咸鱼同桌"}`。
- 接口需要控制台令牌，带智能体令牌或智能体调用标记时拒绝访问。

## 验证与部署

`npm run test:conversation-roles` 验证群/普通私聊/管理员私聊隔离、权限、上下文切换、持久化、迁移和损坏数据保护。`npm run test:group-roles` 验证旧群接口及失败保护。`npm run test:group-roles:ui` 使用 Playwright 将控制台请求接入真实 Bridge 的隔离实例，覆盖群和两类私聊；不访问真实 QQ 或模型。

更新运行时需要 `src/bridge.js`、`src/group-roles.js`、`src/conversation-roles.js`、`src/conversation-sessions.js`、`public/console.html`；账号登录还需要 `src/console-auth.js`、`public/login.html`、`public/viewer.html`；费用统计需要账本模块。先备份，再检查语法并更新，只重启 Bridge。保留线上配置、状态、角色卡、DSH 和 QQ 登录，不将服务器运行数据提交到公开仓库。

人设写法可以参考 [10 张人设备选与生成人设提示词](PERSONA_IDEAS.md)。
