# 成员人设与多机器人入口

管理员从控制台顶部进入“机器人管理”，添加已经部署的本机 Bridge 连接：名称、预期 QQ、回环端口和机器令牌。新连接默认停用；先核验 QQ 身份，再启用。页面不会回显已保存的机器令牌，留空保存表示保持原令牌。主机器人连接不可在这里改端口或移除。此页面只管理连接，不安装程序或执行服务器运维。

顶部“当前机器人”选择器决定控制台管理的目标；账号与授权始终由主后台统一管理。新增普通账号默认没有权限。授权每行一个对象，例如：

```text
primary/group:123456
friends-bot/private:123456
```

`primary` 为主机器人 ID。群号与私聊 QQ 即便相同也分别授权；不同机器人的同一个群也分别授权。旧 `group:123456` 写法仍表示主机器人。修改账号权限或禁用账号后，既有登录会话会被撤销。

## 普通账号可以做什么

登录后进入“我的机器人”，选择已授权的机器人。普通账号可以查看其指定对象的概况、当前人设、会话数量和费用估算；可以创建、复制、编辑自己的角色卡，并应用到指定对象。不能修改全局配置、读取聊天正文、获取模型对话 ID 或机器令牌，也不能管理机器人连接或其他账号。

每张卡拥有独立 ID。不同用户或不同机器人可以用相同显示名，保存时不会覆盖彼此。管理员模板可直接只读应用，或复制成自己的卡再改；普通账号不能修改模板或枚举他人的私人卡。

## 保存、应用与恢复

1. 选择已有角色卡、管理员模板或“新建角色卡”。模板正文可以直接复制编辑，保存后成为一张新的独立卡。
2. 填写名称与正文，点击“保存角色卡”。新卡保存不会自动应用。已有卡若正在使用，页面会列出受影响的授权对象，保存前再次确认。
3. 选择一个已授权对象，点击“应用已保存的人设”。切换沿用现有会话存档机制，不会自动发送消息或唤醒模型。
4. 要重新跟随管理员全局默认，选择“沿用全局人设”并应用。
5. “历史版本与恢复”可预览和恢复旧正文；恢复会追加新版本，原历史保留。

多人或多浏览器同时编辑时，旧版本保存会被拒绝，编辑框里的草稿仍保留。需要放弃草稿并读取最新版时，点击“重新载入已保存版本”。切换机器人或角色前，页面会询问是否放弃未保存内容。

如果某张卡仍被账号已无权管理的对象使用，普通账号不能继续修改它以免影响越权对象；可以复制新卡，再应用到自己当前有权管理的对象。管理员可以在成员管理页面查看和管理全部成员卡；旧人格文件编辑器会引导管理员进入这个页面，保护版本记录。

## 存储与验证

服务位于 `src/member-personas.js`。角色显示名与内部文件名分离；内部角色名使用生成的 `member_` 加32位十六进制 ID，用户输入不作为路径。服务通过同步 SQLite 文档适配器、角色读写回调和事务写入当前版本与历史。损坏或未知版本存储会拒绝改写；已提交但兼容镜像失败的错误不会反向覆盖数据库。

接口包括主机器人 `/api/member/overview`、`/api/member/personas` 与其 `create/update/apply/history/restore` 子路由。其他机器人使用 `/api/bots/:botId/member/...`。更新和恢复必须携带当前 `version`；应用时必须再次校验机器人和精确对象范围。

隔离验证脚本：

- `scripts/test-member-personas.mjs`：服务权限、同名隔离、CAS、历史、事务失败与存储损坏。
- `scripts/test-member-ui.mjs`：成员界面与双机器人交互；实际成员服务配合本机模拟连接。
- `scripts/test-member-real-ui.mjs`：真实 Bridge + SQLite + 登录 Cookie + 浏览器联调。

这些验证不发送真实 QQ 消息或请求付费模型。
